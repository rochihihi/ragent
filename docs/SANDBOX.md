# RAgent 执行沙箱（实验功能）

## 如何使用

默认 `required`：默认进程调用必须使用沙箱。在 **设置 → 执行沙箱** 中检查环境；Windows 初次使用需点击“安装 Windows 沙箱…”并确认 UAC。该步骤会创建 `srt-sandbox` 专用账户、`sandbox-runtime-users` 用户组和按账户 SID 限制出站连接的 WFP 规则。不在工具执行时自动安装，不安装 MITM 根证书。

尚未安装或隔离失败时，默认命令不会执行，也不会静默切换到普通模式。桌面窗口、浏览器登录或其他隔离不兼容操作，可以提出 `execution_mode="host"` 的**新调用**，说明具体原因，经用户本次独立审批后在沙箱外执行。不需要关闭全局沙箱；其他默认调用仍隔离。该机制适用于 `run_command`、`start_terminal`、`run_tests` 和本地 stdio `mcp_call`，不是仅针对 HTML 的特例。

设置中的 `allow_approved_host_execution` 默认开启，表示允许提出申请，不是预先授权。关闭后采用严格策略，普通审批也不能绕过。host 调用不复用“完全授权”、历史命令或会话授权；只允许本次批准。向 host 终端发送后续输入也必须重新批准。host 程序及其子进程拥有当前用户权限（不是管理员提权），不受沙箱文件/网络规则约束；结果明确标记无沙箱，不能宣传为隔离执行。默认浏览器打开 HTML 可能复用已有进程，联网和页面脚本不在命令沙箱内；打开请求被系统接受也不能证明窗口已显示。

host 审批必须来自原生桌面窗口能力令牌，普通 HTTP 请求即使伪造 UI 标记也不能批准。审批预览后执行策略或 MCP 配置变化会使请求失效，需重新核对。MCP 管理界面也提供独立的“本次沙箱外测试…”按钮，显示完整启动命令并确认风险；不会失败后自动切换，普通“测试连接”仍走默认策略。远程 HTTP MCP 不需要此本地进程例外，它的远端副作用本就不在本机沙箱里。

用户仍可明确选择全局 `off` 并确认风险，但这与逐次 host 例外是两回事。修改设置仅影响后续调用，不能把已经运行的进程“补进”沙箱。

源码运行需 Node.js >=22.12，以及：

```powershell
npm --prefix sandbox/runtime ci --ignore-scripts --registry=https://registry.npmjs.org
```

EXE 构建脚本打包 Node、锁定的运行库、Windows helper 和许可证。Python 测试使用外部 Python/项目虚拟环境，**不再在桌面主进程运行项目 pytest**。MCP 服务自身需要的 Python/Node/业务依赖仍需另外准备。

Windows 单文件 EXE 的运行库位于 PyInstaller 私有解压目录。启动前使用上游 holder-PID ACL 租约，仅为 `srt-sandbox` 账户临时授予 `sandbox/runtime` 子树读取、执行权限和必要的父目录遍历权限，不开放整个 `_MEI` 或用户临时目录，不授予运行库写权限。否则上游在普通文件授权之前执行的 WFP 自检无法启动 helper。正常退出、初始化失败均撤销本次租约；异常强制结束后的清理仍受上游崩溃恢复限制。

“检查环境”现在也验证 WFP 的实际阻断效果，并在隔离环境启动内置 Node 执行固定自检代码；只有启动和清理均成功才报告通过。检查过程与任务共用 Windows 执行锁，不授予项目写权限，不执行用户任务，不联网访问外部站点，也不会自动安装账户或修改服务。检查通过仍不能证明任意外部编译器/MCP 依赖均可运行。

锁定的 Windows helper 的 `ReadDeny` 实际禁止全部文件访问（含写入、删除）。同一 holder 对同一路径又声明 `WriteDeny` 会覆盖为较弱的只禁写掩码，因此受保护配置在 Windows 仅发送强 `denyRead`，不重复发送 `denyWrite`；运行库仍单独禁止写入。其他平台继续同时发送读、写拒绝。此行为经过实际子进程读取/写入测试确认，而非只检查返回的 `sandboxed` 标签。

沙箱设置保存在 `%APPDATA%\RAgent\sandbox.json`，不从工作区读取。普通 HTTP 请求不能保存/安装：这些端点需要仅通过桌面 JS bridge 提供的本次启动能力令牌，不在 HTML、模型上下文或配置文件中下发。此措施不防御已控制宿主用户账户/桌面窗口的攻击者。

原生文件工具也禁止修改/删除 RAgent 的宿主配置目录，即使会话拿到了该目录的通用写权限。否则模型可能通过修改 `sandbox.json` 间接关闭隔离；宿主配置修改必须走用户设置界面。

## 覆盖与边界

| 执行路径 | 边界 |
| --- | --- |
| `run_command`、持续终端、pytest/其他验证命令、结构化 Git 子进程 | 统一沙箱入口；审批不会关闭隔离 |
| 外部 stdio MCP | MCP SDK 启动沙箱 broker，再在隔离环境中启动服务；连接测试也经过同一入口 |
| 原生文件读写/补丁 | 仍由 SafeWorkspace 的路径授权、哈希及事务规则控制，不在独立 OS 进程沙箱内 |
| HTTP MCP、模型 API | 宿主客户端负责连接；远端服务器副作用不在本机沙箱内，仍需审批与可信服务 |
| 桌面 GUI / 沙箱不兼容操作 | 提出 host 新调用，明确风险并本次独立批准；不会自动降级或关闭其他调用的沙箱。严格策略可完全禁止 |

策略只额外授予工作区及明确批准路径的写权限，同时允许运行库的临时区域。Windows 文件访问还取决于专用账户/受限 token 的基础权限，不能将此 alpha 适配称为全盘逐路径访问白名单。读取也并非严格全盘白名单：额外保护 RAgent 配置、SSH/AWS/Codex 配置及用户凭据文件；覆盖这些目录的宽泛授权拒绝执行。机器可公开读取的系统文件仍可能可读。操作系统沙箱不等于文件备份，授权工作区内仍可能发生破坏。

网络通过 SRT 代理和系统隔离限制。默认域名白名单为空；用户可手工允许具体域名（例如 `registry.npmjs.org`）。模型不能在工具参数中放宽域名规则。新的会话动作审批指纹绑定沙箱策略，修改策略后该类旧授权不自动沿用；required 模式也不沿用没有策略绑定的历史命令列表。授权额外工具目录只允许读取，不额外授予写权限。

Windows 使用上游 **alpha** 后端：专用用户 + restricted token + Job Object + NTFS ACL + WFP。Ragent 的 Windows 本地沙箱进程串行持有跨进程锁，避免本应用不同工作区共用账户交叉授权；其他软件使用同一 SRT 账户的并发不在此锁的协调范围内。不适合互不信任的多租户共用主机。

限制：系统 DNS 服务查询不被 Windows WFP 连接规则阻断；专用账户不能访问未授权的用户目录编译器；Git 的全局身份配置可能不可读，可为仓库设置本地身份；不承诺抵御管理员、内核漏洞或所有运行库逃逸。macOS/Linux 依赖原生 Seatbelt/bubblewrap 等依赖，尚需在对应系统实测。

停止/超时终止已知 broker 进程树；正常退出等待上游 reset 清理授权。非正常退出的 ACL 恢复还依赖上游下一次初始化的崩溃恢复，不能保证强制退出时已经立即移除所有 ACL。Windows 账户和 WFP 规则是安装级资源，不随一次命令退出删除；卸载遵循上游 `windows-uninstall` 指引，需要用户确认。

## 依赖与测试说明

底层复用 [Anthropic Sandbox Runtime](https://github.com/anthropics/sandbox-runtime)，固定 npm `0.0.78`，保留其 Apache-2.0 许可；不是复制 Claude Code 闭源客户端或 Devin 核心代码。Node 自身许可随 EXE 打包。

Windows helper 使用同一版本的最小 ACL 修复构建：父目录 `FILE_DELETE_CHILD` 拒绝只作用于父目录自身，不向整个用户目录递归传播；没有变化的 ACL 不重复更新。仅对象权限更新保留继承条目与保护标志；工作区授权和受保护目录的读写拒绝仍按子树传播。这样避免执行简单命令前递归更新用户目录造成超时，不删除凭据保护，不关闭沙箱，也不自动切换宿主执行。补丁在 `sandbox/patches/windows-acl.patch`，构建入口为 `scripts/build_sandbox_helper.py`，来源和哈希在 `sandbox/runtime/windows-helper.json`；EXE 构建会检查二进制和补丁哈希。租约恢复或撤销失败时不报告环境检查成功。工具启动期间前端显示“执行工具”，不再误显示“整理上下文”。旧版本留下的继承 ACL 仍需上游恢复流程清理，本修复不等于生产级安全审计。

当前锁文件 `node-forge 1.4.0` 被 npm audit 标记 RSA 签名验证 advisory（[GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv)）。本适配不启用 TLS termination/证书验证功能，不能据此宣称整个依赖树无漏洞；后续升级须重新审计和测试，不能盲目按 audit 建议降级到缺少 Windows 后端的旧版。Windows alpha 不应宣传为生产级强安全隔离。

自动化测试覆盖策略校验、缺依赖拒绝、不自动安装/降级、审批绑定、argv 边界、配置接口授权、终端及 MCP 接入。Windows 真实账户/WFP 安装与跨边界阻断测试需用户显式批准安装后另行进行；mock 测试不能证明操作系统隔离有效。
