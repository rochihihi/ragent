# 幂等与恢复

幂等针对“同一次操作的重复交付”，不是禁止用户再次执行相同参数。

## 消息提交

- `POST /studio-api/sessions/{id}/messages` 接受 `message_id`，前端每次成功发送使用新 ID。网络报错后的重试保留原 ID，直到成功或修改内容；当前界面内保存该重试身份，关闭/重载界面后不保留。
- 唯一键为 `(session_id, message, message_id)`，内容使用规范化 JSON 的 SHA-256 指纹。原 ID + 原内容返回首次响应；原 ID + 不同内容返回 409，不修改会话。
- 接受记录、会话状态与事件在同一个 SQLite 事务中提交，提交后才启动 Agent。运行中纠正使用同一张持久化请求表，不因重试重复排队。
- 旧客户端不提供 ID 时由服务端生成，保留兼容，但无法识别旧客户端的网络重发。
- 重新打开应用只把中断任务恢复为“已暂停”，不会自动执行。点击继续可以恢复已接受但尚未写入聊天历史的消息；重复 HTTP 请求本身只返回回执，不重新启动任务。

## 审批

权限请求 ID 是审批身份。审批决定、授权、待恢复动作和回执原子提交；提交后才恢复执行。相同决定重复提交返回首次结果，改变决定、范围或调整指令返回 409。失败校验会回滚整个事务，不生成成功回执。

审批回执不是长期授权；一次授权、同会话精确匹配授权、单次沙箱外审批的安全边界不变。

## 工具执行

`studio_operations` 保存 `(session_id, operation_id)`、有效参数指纹、状态和结果。执行前使用 `BEGIN IMMEDIATE` 原子领取；任务完成结果与会话快照一起提交。工具执行期间不持有数据库事务。

- 已完成：返回已有结果，不执行第二遍；即使请求持有旧会话快照也以数据库记录为准。
- 待审批：完成审批后可以恢复同一动作。
- 执行中 / 结果不明：暂停并要求核验，不擅自重跑。异常中断会标记 unknown；进程被强杀时留下的 running 也按不明状态处理。
- 原操作 ID 的有效参数变化：阻止执行。严格验证命令和绑定技能脚本路径使用审批展示的有效参数计算指纹。
- 用户明确发起的新动作有新 ID，可重新执行相同参数。不能只对命令文本做哈希然后永久去重。

整批删除仍保留原有准备/回滚流程，并原子领取全部子动作。已领取的子动作不能通过批处理绕过去重。

这提供本机单桌面实例内的去重和安全恢复，**不承诺任意 shell、远程 MCP 或文件系统副作用的 exactly-once**。外部操作成功后、数据库确认前进程崩溃会留下不明结果；只有下游也支持幂等键/查询业务状态时，才可能安全自动恢复。本项目不向任意 MCP 工具注入未声明的幂等参数。

## 技能指标

项目 `.agents/skill-runtime/metrics.sqlite3` 保存以技能名、版本、指标类型、操作 ID 为唯一键的指标回执。命令采样使用工具 ID，任务采样使用任务 ID；重复采样保留首次结果，不额外影响灰度失败率。

注册表只展示最近 100 个采样，数据库仍保留旧身份，避免被窗口淘汰后重试再次计数。旧注册表采样只迁移一次。指标提交后注册表写入失败，再次提交同一个身份会从数据库重建视图，不重复计数。该数据库属于保护的技能运行目录，不应让技能脚本修改。

请求和工具记录在删除会话时一起清理；指标记录随项目运行数据保留，不自动清空去重身份。此版本面向单桌面实例，不是多进程/分布式任务调度器。
