# 会话工作记忆

当前只升级同一会话内的记忆，不读取其他会话，也不建立项目级或全局记忆库。

## 流程

1. 模型可以随原生工具或兼容 JSON 决策返回 `memory_update`；没有更新时传 `null`。
2. 本地记录简短事实、假设、相关路径和失败信息。模型笔记标为 `model_note`；运行时产生的工具观察标为 `tool_observation`，附原始观察下标；旧数据缺少来源时标为 `legacy`。
3. 每次构建上下文，通过 **BM25 + 本地向量语义检索 + RRF**，从当前会话已保留的笔记中筛选。BM25 支持英文标识符、路径及中文双字；多语言向量可召回不同措辞的相关笔记。新近程度仅用于同分排序，不保证所有语义都能召回。
4. 投影默认最多 9,000 个 JSON 字符（含来源信息），再接受现有 Token 预算控制。事实/假设/路径/失败的保存上限分别为 80/40/80/40 条；原始对话和工具观察不会因此删除。
5. 同一 `session_id` 的笔记和来源信息随会话存入 SQLite。重启后恢复该会话仍可使用；新建会话为空，即使项目目录相同。

`structured_memory.provenance` 中各分类数组与对应笔记数组按位置对齐。
工具来源表示某次历史观察确实发生过，不代表当前文件内容、进程状态或测试结果仍然相同。

## 纠正与安全

- 模型可使用 `forget_facts` / `forget_hypotheses` 精确撤回自己写入的笔记，再加入新笔记；不执行模糊删除。没有来源的旧笔记和工具证据不能通过这两个字段删除。
- 删除笔记不会删除原始消息/观察，也不撤销已经发生的文件写入或外部操作。
- 常见 API Key、Bearer Token、密码等模式在新增笔记、记忆投影和新生成交接摘要中脱敏；这是尽力保护，不是完整的秘密检测。原始对话与工具日志不属于这次清洗范围。
- 当前用户请求与运行时证据优先。记忆、摘要和模型推断都不能授予权限或覆盖新指令。
- 仍沿用现有历史压缩机制：按覆盖范围生成交接摘要，保留近期原文；失败保留旧摘要，原始历史不改写。不为每次记忆更新额外请求一个后台模型。

例如：同一对话中先讨论退款逻辑，随后查看了大量其他文件，再问退款如何计算，较早的相关笔记仍有机会被选入上下文；另开新对话则不会继承它。

## 混合检索实现

- 稀疏分支：Python 内实现 BM25（k1=1.2，b=0.75），计算词频、逆文档频率及长度归一化，不是简单数重叠关键词。
- 稠密分支：固定版本的 multilingual MiniLM-L12-v2 INT8 ONNX，CPU 推理，注意力掩码平均池化，再 L2 归一化和余弦相似度。支持中英文；这是独立的本地嵌入模型，与对话使用 OpenAI / DeepSeek 无关，不需要额外密钥，也不向服务商发送待检索笔记。
- 融合：取最多 40 条正 BM25 命中、最多 40 条余弦相似度 >0.25 的命中，按 `sum(1/(60+rank))` 融合（rank 从 1 开始）。不直接相加量纲不同的分数。无命中项仍可作为较新的补充；沿用各类保底及总预算。
- 嵌入输入：脱敏后的短笔记、当前查询（均最多 500 字符），模型截断至 128 token。原始对话、凭据配置、授权规则不进入嵌入索引。脱敏仍不能保证发现所有秘密。
- 缓存：进程内最多 8 个会话，按工作区路径 + session_id 隔离，每会话最多 240 条笔记及当前查询。仅新增/修改文本重新嵌入，撤回笔记与旧查询从该缓存清除；不检索其他会话。缓存不是数据库，重启后从当前会话的 SQLite 笔记重建。
- 一致性：每次检索先复制笔记与来源快照，避免异步推理期间内容变化导致分数错配。模型与分词数据固定版本、构建及首次加载核验 SHA256；更新模型需重新构建，进程缓存不会跨版本复用。
- 响应性：单工作线程、CPU 两线程、每批最多 8 条；不排队堆积请求。忙碌、加载/数据/推理失败、15 秒超时均降级到 BM25。暂停可取消等待；已开始的 CPU 推理可能在后台结束，但不修改会话或执行任何工具。
- 可观察性：上下文 `structured_memory.retrieval_status` 和执行记录 `memory_retrieval` 区分 `hybrid_local`、`bm25_configured`、`bm25:no_query_or_notes`、`bm25_fallback:embedding_busy/embedding_timeout/embedding_unavailable`。失败不伪称混合检索，也不把原始异常内容写入提示词。

EXE 已内置模型、分词数据及许可证，运行不下载模型、不需要 GPU。这会增加 EXE 体积和首次加载开销。
源码开发环境需先安装项目依赖，再运行：

```powershell
python scripts/prepare_memory_model.py
```

模型仅下载至被 Git 忽略的 `build/memory-model/`；不把模型权重提交到仓库。
离线缺少数据时仍可使用 BM25；设置环境变量 `VERIPATCH_MEMORY_RETRIEVAL=bm25` 可显式关闭语义分支。
此环境变量不改变模型服务商配置、沙箱或审批策略。

测试覆盖真实中英文语义召回、精确路径、RRF、非法向量、超时/并发/取消、缓存失效/上限、会话隔离、脱敏及 JSON 预算；EXE 自检也必须运行真实离线检索。

算法与模型参考：[Sentence Transformers 模型与池化说明](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)、[ONNX 导出](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2)、[RRF](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)。模型许可与来源见 [NOTICE](memory-model/NOTICE.md)。
