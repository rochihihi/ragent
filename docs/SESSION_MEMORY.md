# 会话工作记忆

当前只升级同一会话内的记忆，不读取其他会话，也不建立项目级或全局记忆库。

## 流程

1. 模型可以随原生工具或兼容 JSON 决策返回 `memory_update`；没有更新时传 `null`。
2. 本地记录简短事实、假设、相关路径和失败信息。模型笔记标为 `model_note`；运行时产生的工具观察标为 `tool_observation`，附原始观察下标；旧数据缺少来源时标为 `legacy`。
3. 每次构建上下文，根据当前请求的关键词相关性和新近程度，从当前会话已保留的笔记中筛选。支持英文标识符、路径和中文双字匹配；不是向量检索，也不保证语义召回。
4. 投影默认最多 9,000 个 JSON 字符（含来源信息），再接受现有 Token 预算控制。事实/假设/路径/失败的保存上限分别为 80/40/80/40 条；原始对话和工具观察不会因此删除。
5. 同一 `session_id` 的笔记和来源信息随会话存入 SQLite。重启后恢复该会话仍可使用；新建会话为空，即使项目目录相同。

`structured_memory.provenance` 中各分类数组与对应笔记数组按位置对齐。
工具来源表示某次历史观察确实发生过，不代表当前文件内容、进程状态或测试结果仍然相同。

## 纠正与安全

- 模型可使用 `forget_facts` / `forget_hypotheses` 精确撤回自己写入的笔记，再加入新笔记；不执行模糊删除。没有来源的旧笔记和工具证据不能通过这两个字段删除。
- 删除笔记不会删除原始消息/观察，也不撤销已经发生的文件写入或外部操作。
- 常见 API Key、Bearer Token、密码等模式在新增笔记、记忆投影和新生成交接摘要中脱敏；这是尽力保护，不是完整的秘密检测。原始对话与工具日志不属于这次清洗范围。
- 当前用户请求与运行时证据优先。记忆、摘要和模型推断都不能授予权限或覆盖新指令。
- 仍沿用现有历史压缩机制：按覆盖范围生成交接摘要，保留近期原文；失败保留旧摘要，原始历史不改写。不为每次记忆更新额外请求一个后台模型。

例如：同一对话中先讨论退款逻辑，随后查看了大量其他文件，再问退款如何计算，较早的相关笔记仍有机会被选入上下文；另开新对话则不会继承它。
